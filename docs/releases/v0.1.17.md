## Fixed

**"Open Folder" opened the wrong folder.** ([#8](https://github.com/ahmadfarooqofficial/Fast-Download-Manager/issues/8))
The file's path was handed to the button as a piece of JavaScript, where every
backslash is an escape character. `C:\Users\…` arrived as `C:Users…`, Explorer
could not make sense of it and opened whatever folder it felt like — or, for
some paths, nothing happened at all. "Open File" from the list had the same
problem. Both now look the file up by its row instead, and Explorer is asked for
the selection in the one form it actually honours.

**Removing a finished download never deleted the file.** ([#8](https://github.com/ahmadfarooqofficial/Fast-Download-Manager/issues/8))
"Remove" only ever took the row out of the list, which is not what everyone
expected it to do. It now asks: delete the file from disk too, or keep it. The
answer is yours each time; nothing is deleted without being asked.

**The category badge in the download popup was wrong.** ([#7](https://github.com/ahmadfarooqofficial/Fast-Download-Manager/issues/7))
Until a download actually started, the popup had no category to show and fell
back to "Video" — so an installer sat there labelled as a film while the "Save
to" path beside it correctly said `Programs`. The category is now decided the
moment a download is added, by the same rule that picks the folder, so the two
always agree.

**A popup for a download that was already removed** could be left open with
nothing in it. It now closes itself.

## Known limitations

- Not code-signed, so Windows shows an "unknown publisher" warning on install.
  Click **More info → Run anyway**.
- The browser extension is not on the Chrome Web Store yet, so Chrome will ask
  you to enable it once after installing.
- The installer is available in 8 languages; the app itself has 12.
