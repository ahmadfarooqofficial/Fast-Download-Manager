## Fixed

**Deleted downloads came back after a restart.** ([#10](https://github.com/ahmadfarooqofficial/Fast-Download-Manager/issues/10))
The download list is saved on every change by writing a temporary file and
renaming it into place. On Windows, an antivirus scanner or the search indexer
can hold a freshly written file for a few milliseconds, and the rename fails
while it does. Any later change repaired the file — but when the deletion was
the last thing you did before shutting down, nothing came after it, and the
deleted rows were there again at the next start, in whatever state they had
been in. Saves now retry briefly and, if the rename still cannot go through,
write the list in place. A failed save is also logged as an error rather than a
warning.

**A blank white popup window.** ([#10](https://github.com/ahmadfarooqofficial/Fast-Download-Manager/issues/10), [#8](https://github.com/ahmadfarooqofficial/Fast-Download-Manager/issues/8))
When the browser handed FDM a download right as FDM was starting — typically
the first download after a reboot — the download popup could be created before
the app's own window had finished coming up, and came up white, having never
run a line of its page. Deleting the download did not close it either, because
the popup's own script was what would have closed it. Three things changed:
popups now wait until the main window has loaded; a popup that has not loaded
within a few seconds is reloaded once and closed if it still shows nothing;
and removing a download closes its popup from the app itself. While it loads, a
popup is drawn in the app's dark colour rather than white.

## Known limitations

- Not code-signed, so Windows shows an "unknown publisher" warning on install.
  Click **More info → Run anyway**.
- The browser extension is not on the Chrome Web Store yet, so Chrome will ask
  you to enable it once after installing.
- The installer is available in 8 languages; the app itself has 12.
